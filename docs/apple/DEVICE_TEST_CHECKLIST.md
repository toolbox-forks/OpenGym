# Physical-device acceptance checklist

WRITTEN — draft acceptance steps, not completed test evidence. Only the Phase 1 shell currently exists; run later checks after PROGRESS marks their implementation available. Native Release/simulator evidence is still required before device acceptance. Use a test profile and record commit, Xcode version (owner reports 27.0), iOS/watchOS versions, device models and outcomes.

Install/signing and initial Health authorization are prerequisites outside the timed run. Follow XCODE_SETUP and B-03, enable matching HealthKit/app-group entitlements once those targets exist, install iPhone/Watch apps, and select local mode. Seed a three-set routine and one timed/cardio exercise after the Watch implementation is available. Test steps below target under 30 minutes total.

1. **iPhone shell (2 min, Phase 1):** open Plan, Stats and Exercises; search, start a freestyle workout, add an exercise, adjust load/reps and complete a set. Expected: existing functionality works with no server, notch and home indicator do not cover controls.
2. **Keyboard and haptics (2 min, Phase 1):** edit a bottom-screen numeric field, rotate and dismiss the keyboard while the sheet stays open. Tick a set with Vibrate enabled, then disabled. Expected: focused field and buttons remain reachable; UIKit feedback occurs only while enabled; no doubled safe-area gap.
3. **Watch start/context (2 min, Phase 4):** choose the seeded routine from app, then complication/Smart Stack once Phase 8 exists. Expected: name/thumbnail, previous load/reps, progression reason, set tag and enabled RIR/RPE match the phone.
4. **Offline wrist logging (3 min, Phases 4–5):** turn off the phone or leave it out of range. Confirm three prefilled sets, adjust load/reps with Crown on one, log effort. Expected: confirmation needs one tap, increment matches exercise, haptic detents occur, phone absence blocks nothing.
5. **Editing and exercise modes (2 min, Phase 4):** add/reorder/replace/skip an exercise, add/delete a set, alternate a superset, record a timed and cardio entry. Expected: current exercise/order and totals remain correct; no previously completed set is lost.
6. **Rest and Always-On (2 min, Phase 4):** let a short rest run with wrist down, add 15 seconds, skip another. Expected: readable dim rest display, deadline remains correct and a distinct haptic occurs on expiry; timers do not depend on the phone.
7. **Live Health session (2 min, Phases 3–4/7):** keep the workout running while navigating away/locking the Watch. Expected: heart rate, zone and active energy continue updating; return to the correct session; summaries include average/max and rest recovery, raw samples stay in Health.
8. **Interruption recovery (2 min, Phase 4):** terminate and relaunch the Watch app after logging a set; if safe, reboot with the workout unfinished. Expected: exact recorded sets/order/rest deadline survive; Health session recovery handles the OS state without inventing missing sensor samples.
9. **Finish and duplicate-free delivery (2 min, Phases 3–5):** finish on the Watch while the phone is still absent, then reconnect and relaunch both apps twice. Expected: exactly one iPhone history workout and exactly one Health workout, matching UUID/times/sets/energy; retries create no duplicates.
10. **Reachable concurrent edits (2 min, Phase 5):** edit different sets on phone and wrist, then edit the same set with a later timestamp. Expected: independent edits survive; later same-set edit wins; finished offline outbox is not discarded.
11. **Measurements and recovery (2 min, Phases 3/9):** log body mass, waist and body-fat once; import an existing Health reading and refresh twice. Expected: correct kg/lb/metre/percentage conversion and no duplicates; sleep/HRV/resting HR show source attribution, including Oura when its app has supplied Health data.
12. **Integrations (2 min, Phase 8):** lock iPhone during rest; use +15/skip on Live Activity, run Start workout/Log body weight Shortcuts, inspect widgets. Expected: controls update the actual rest/session and widgets show the latest persisted state.
13. **Hardware controls (1 min, Phases 4/8):** where hardware supports them, use Action button and Double Tap to complete a set once. Expected: one completed set per gesture. Record hardware limitations as device-only BLOCKED checks, rather than claiming a simulator verified them.
14. **Progress/privacy/accessibility (2 min, Phases 7/10):** inspect updated PRs/HR/recovery/weekly volume, export a summary and CSV, use VoiceOver and large Dynamic Type. Expected: no hidden controls, no clipped values, correct summaries, local photos and visible exercise attribution; no analytics or health upload outside the owner's selected instance.

For each item record VERIFIED with the exact steps/result, or BLOCKED with the device/owner requirement in BLOCKERS. Mark failed behaviour as a failure to fix; do not treat it as a hardware limitation. Simulator tests cannot verify live sensors, background lifetime, physical haptics or physical WatchConnectivity. Oura Tier 2 live OAuth is a separate optional owner-credential check (B-05).
